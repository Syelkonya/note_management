# Notes Service

A small REST API for managing personal notes, built with **Spring Boot 3.5.16** and **Java 17**.
Notes are stored **in memory** — there is no database and no external infrastructure to
provision. The service exposes plain JSON endpoints for creating, reading, updating,
filtering and deleting notes.

## Overview

- Full CRUD over notes: create, list, filter by tag, fetch by id, update, delete.
- Server-owned identity and timestamps: `id` (UUID) and `createdAt` (ISO-8601 instant)
  are generated by the server; clients cannot set them.
- Server-side tag normalization: tags are trimmed, lower-cased, de-duplicated and
  blank values are dropped.
- Consistent error responses in [RFC 9457 `ProblemDetail`](https://www.rfc-editor.org/rfc/rfc9457)
  format (`application/problem+json`) for validation errors, malformed ids and missing notes.
- No persistence: data lives only in the JVM heap and is lost when the process stops.
  The service is meant for local development, demos and tests.

## Stack

| Layer            | Choice                                                          |
|------------------|-----------------------------------------------------------------|
| Language         | Java 17                                                         |
| Framework        | Spring Boot 3.5.16 (Spring Web MVC, Bean Validation, Jackson)   |
| Build            | Maven via the bundled Maven Wrapper (`mvnw` / `mvnw.cmd`)       |
| Tests            | JUnit 5 + Mockito + Spring Boot Test / MockMvc                  |
| Storage          | In-memory repository (`ConcurrentHashMap`-backed)               |
| Boilerplate      | Lombok — `@RequiredArgsConstructor`, `@Getter`, `@UtilityClass` |
| Container        | Multi-stage Docker image, `eclipse-temurin:17-jre-alpine`       |

Lombok is a compile-time-only dependency: it generates the boilerplate while the code is
compiled, has no runtime footprint and is excluded from the executable fat jar.

## Requirements

- **JDK 17 or newer** (`java -version`) for local builds and runs.
- **Docker** (optional, only for the container path). The Docker daemon must be running.
- **Network access on the first build**: the Maven Wrapper downloads Apache Maven 3.9.6 and
  Maven downloads the project dependencies (Spring Boot, starters, test libraries).
- Maven itself does **not** need to be installed — the wrapper takes care of it.

## Build, test and run locally

The project ships with the Maven Wrapper, so the commands work without a global Maven
installation.

```bash
# Run the test suite
./mvnw test

# Clean build: compile, run the full test suite and produce the executable jar
./mvnw clean verify

# Build the jar without running tests
./mvnw -DskipTests package

# Start the application locally on http://localhost:8080
./mvnw spring-boot:run
```

On **Windows** use `mvnw.cmd` instead of `./mvnw`:

```powershell
.\mvnw.cmd test
.\mvnw.cmd clean verify
.\mvnw.cmd spring-boot:run
```

After `./mvnw clean verify`, the runnable artifact is
`target/notes-service-0.0.1-SNAPSHOT.jar` and can also be started directly with
`java -jar target/notes-service-0.0.1-SNAPSHOT.jar`.

The application listens on port **8080** (`server.port` in
`src/main/resources/application.properties`). Override it with
`--server.port=9090` or the `SERVER_PORT` environment variable.

## Run with Docker

The multi-stage `Dockerfile` builds the jar with the Maven wrapper and copies only the
executable jar into a small Alpine JRE image. The application runs as a non-root user
(`appuser`) and exposes port 8080. Because `.dockerignore` excludes `target/`, the local
build output is not sent to the daemon.

```bash
# Build the image
docker build -t note-management-app:latest .

# Run the container (foreground; Ctrl+C to stop)
docker run --rm -p 8080:8080 note-management-app:latest

# Run in the background with a custom port mapping
docker run -d --name note-management-app -p 8080:8080 note-management-app:latest
```

The API is then available at <http://localhost:8080/notes>. The first `docker build` needs
network access to download the Maven distribution, dependencies and base images; later
builds are fast thanks to the cached dependency layer (`dependency:go-offline`).

## API

Base URL: `http://localhost:8080`. All request and response bodies are JSON
(`Content-Type: application/json`); error bodies are `application/problem+json`.

| Method | Path              | Request body / query      | Success response                              | Error responses                    |
|--------|-------------------|---------------------------|-----------------------------------------------|------------------------------------|
| POST   | `/notes`          | `NoteRequest` JSON        | **201 Created**, `Location: /notes/{id}`, created note | **400 Bad Request** (validation)   |
| GET    | `/notes`          | —                         | **200 OK**, JSON array of notes               | —                                  |
| GET    | `/notes?tag=work` | `tag` query parameter     | **200 OK**, JSON array of matching notes      | —                                  |
| GET    | `/notes/{id}`     | `id` path (UUID)          | **200 OK**, the note                          | **400** malformed UUID, **404** not found |
| PUT    | `/notes/{id}`     | `NoteRequest` JSON        | **200 OK**, the updated note                  | **400** validation / malformed UUID, **404** not found |
| DELETE | `/notes/{id}`     | —                         | **204 No Content**                            | **400** malformed UUID, **404** not found |

### Payloads

`NoteRequest` (create and update):

```json
{
  "title": "Buy milk",
  "content": "2 liters, semi-skimmed",
  "tags": ["shopping", "home"]
}
```

| Field     | Required | Constraints                          |
|-----------|----------|--------------------------------------|
| `title`   | yes      | not blank, at most 255 characters    |
| `content` | no       | at most 10 000 characters            |
| `tags`    | no       | set of strings; normalized by server |

`NoteResponse`:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Buy milk",
  "content": "2 liters, semi-skimmed",
  "createdAt": "2026-01-15T09:30:00Z",
  "tags": ["shopping", "home"]
}
```

### Server-generated values

- `id` — a random UUID assigned by the server on creation; it never changes afterwards.
- `createdAt` — an ISO-8601 `Instant` (UTC) captured once at creation time; it is not
  modified by `PUT`.
- Tags are **normalized before storage**: each tag is trimmed, converted to lower case,
  blank tags are dropped, and duplicates are removed. For example
  `[" Work ", "WORK", "", "  ", "home"]` is stored and returned as `["work", "home"]`.
  Consequently, `GET /notes?tag=work` matches notes tagged `Work`, `work` or ` WORK ` —
  tag filtering is case-insensitive and uses the same normalization.

### curl examples

All examples assume the service is running on `http://localhost:8080`.

**Create a note** — returns `201` with a `Location` header:

```bash
curl -i -X POST http://localhost:8080/notes \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk","content":"2 liters, semi-skimmed","tags":["shopping"," Home "]}'
```

**List all notes**:

```bash
curl http://localhost:8080/notes
```

**List notes by tag** (case-insensitive; `work`, `Work`, `WORK ` all match):

```bash
curl "http://localhost:8080/notes?tag=work"
```

**Get a note by id** (replace the id with one returned by `POST` / `GET`):

```bash
curl http://localhost:8080/notes/3fa85f64-5717-4562-b3fc-2c963f66afa6
```

**Update a note** — replaces `title`, `content` and `tags`; `id` and `createdAt` are kept:

```bash
curl -i -X PUT http://localhost:8080/notes/3fa85f64-5717-4562-b3fc-2c963f66afa6 \
  -H "Content-Type: application/json" \
  -d '{"title":"Buy milk and bread","content":"2 liters + 1 loaf","tags":["shopping","food"]}'
```

**Delete a note** — returns `204 No Content`:

```bash
curl -i -X DELETE http://localhost:8080/notes/3fa85f64-5717-4562-b3fc-2c963f66afa6
```

> **Windows PowerShell:** `curl` is an alias for `Invoke-WebRequest` and does not accept
> these flags. Use `curl.exe` instead of `curl`, or use `Invoke-RestMethod`, e.g.
> `Invoke-RestMethod -Uri http://localhost:8080/notes -Method Get`.

### Error responses (ProblemDetail)

Errors are rendered as Spring `ProblemDetail` documents with content type
`application/problem+json` and the standard RFC 9457 members. Example for a missing note
(`GET /notes/{id}` with an unknown id):

```json
{
  "type": "about:blank",
  "title": "Note not found",
  "status": 404,
  "detail": "Note not found: 3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "instance": "/notes/3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "noteId": "3fa85f64-5717-4562-b3fc-2c963f66afa6"
}
```

Example validation failure for `POST /notes` with a blank title:

```json
{
  "type": "about:blank",
  "title": "Validation failed",
  "status": 400,
  "detail": "The request body contains invalid fields",
  "instance": "/notes",
  "errors": {
    "title": "title must not be blank"
  }
}
```

A malformed UUID in the path (`/notes/not-a-uuid`) is also reported as `400 Bad Request`
with `title: "Invalid request parameter"` and the offending `parameter` property.
Clients should rely on `status` first; `title`/`detail` are human-readable.

## Notes and limitations

- **In-memory storage only**: all notes are lost on restart, and the service is not safe to
  scale horizontally — each instance has its own isolated data set.
- No authentication or authorization: do not expose this service to untrusted networks.
- The repository is concurrency-safe for the in-memory use case, but there is no
  persistence layer to extend here; replacing the `NoteRepository` implementation is the
  intended seam if persistent storage is needed later.
- The Docker image runs as the unprivileged `appuser`; no shell utilities, Maven or sources
  are present in the runtime image — only the JRE and the jar.
